# suyu v0.0.11 (draft)

This release consolidates the ABI 5 static recompiler corrections, improves the
standalone SDL player, and updates cross-platform build support. Static execution
remains experimental; Hybrid AOT + JIT remains the recommended general-purpose
mode.

## Static execution and player

- ABI 5 validates generated image revision, instruction coverage, and memory
  guards more strictly. **Re-export every previously generated static module**
  before using it with this release; ABI 4 bundles are intentionally rejected.
- Fixed-point conversion and FPSR behavior, static dispatch, and diagnostic
  lifetime have additional synthetic regression coverage.
- The standalone SDL player displays timestamped FPS, emulation speed, the
  application's observed CPU backend, and cumulative JIT transitions. Its
  controls panel retains Player 1 bindings and labels a saved controller that
  is disconnected.
- Explicit base/update content selection uses a read-only provider and rejects
  a second, unrelated launch path.
- A wholly zero, zero-address texture descriptor is treated as an unbound image
  during shader format specialization. It uses the existing noninteger fallback;
  malformed nonzero descriptors still take the unsupported-format diagnostic.

## Export Game, Steam, and libretro

- Windows **Source** exports contain a generated C project; they do not label a
  generic emulator copy as a compiled static launcher. Windows **Build**
  exports require the compiled launcher to finish successfully.
- Repeated exports fingerprint effective ExeFS content before reusing generated
  code, remove obsolete staged modules, and invalidate Hybrid caches when the
  Dynarmic fallback policy changes. Known base RomFS / updated ExeFS and
  standalone NCA code/data mismatches are rejected. Two nonbase views from an
  installed update still need title-specific verification before a playable
  package can be claimed.
- Steam shortcut insertion, repair, and removal use checked atomic writes.
  These paths passed an isolated synthetic library test; refresh behavior in a
  running Steam client has not been verified.
- The Vulkan libretro core supports explicit base-plus-update verification,
  optional version metadata for an independently verified deconstructed pair,
  TAS playback, and opt-in game FPS sampling. Clean-profile checks cover key
  adoption, malformed content and failed-load retry paths. ARM64
  Android libretro is an opt-in development build separate from the default APK.

## Builds and validation

Windows GUI/CLI/libretro, Linux GUI/CLI, and macOS arm64 GUI/CLI/libretro
development builds completed. Linux and macOS full test suites and the focused
static-recompiler tests passed. macOS skips 16 fastmem arena tests on its 16 KiB
page host while checking the supported backing-memory fallback. An Android
arm64 debug APK built and passed debug-signature verification; device runtime
and release signing were not tested.

The opt-in Android libretro core also built for ARM64 in an isolated Debug
configuration. That binary was not replayed on a device after the final source
changes. macOS RetroArch loaded the verified v4.0.0/64-bit pair, but its
captured output remained on the loading logo with a guest fault; an on-track
macOS race and race FPS remain unverified. An Android software-rendered emulator
showed on-track movement at low FPS; it is not a physical-device benchmark.

A local strict-static Mario Kart 8 Deluxe v4.0.0 TAS replay reached a rendered,
controllable race segment with zero static-to-JIT transitions. This is a
per-title development test, not a full-race completion, performance claim, or
general title-compatibility guarantee. Physical Xbox input remains unverified
without a connected pad. Firmware applet CPU-backend attribution was not
established.

Release packaging must exclude games, generated game modules, keys, firmware,
and saves. Standard downloads may include Dynarmic; only separately audited
no-JIT builds omit it. Do not infer universal compatibility from one title's
race segment: an isolated Smash Ultimate strict-static boot still hit an
uncovered lookup and later texture-format diagnostics.
