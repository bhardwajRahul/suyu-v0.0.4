# suyu v0.0.11

v0.0.11 makes Export Game something a player can use end to end: pick a game, get a
package you can double-click or launch from Steam, with your controllers, settings and
shader cache carried over. It also brings Apple Silicon Macs back, adds a RetroArch
(libretro) core, and gives the static recompiler a stricter, more accurate code format
(ABI 5).

> **Before you upgrade: re-export your old builds (ABI 4 → ABI 5).**
> Every static or Hybrid game build made with v0.0.10 or earlier must be exported
> again. This release refuses older (ABI 4) builds on purpose instead of running them
> incorrectly. Re-exporting also picks up the fixes below (real update version, shader
> cache, firmware, controllers).

**Which CPU mode should I use?**

- **suyu Dynarmic JIT (Baseline):** the normal emulator, and now the default. It is the
  most compatible, and for Mario Kart 8 Deluxe it is currently the fastest (see
  [Performance](#performance)).
- **suyu Hybrid JIT + AOT** (experimental): runs pre-compiled code and falls back to the
  JIT for anything the pre-compiled code doesn't cover. Performance varies by game;
  compare it with the Dynarmic JIT export.
- **suyu static AOT (Experimental):** pre-compiled code only, with no JIT fallback. Use it
  for testing, not everyday play.

Making pre-compiled code faster on x86 PCs is the next focus.

## Highlights

### Export Game (Windows)
- The CPU backend list now starts with **suyu Dynarmic JIT (Baseline)**, which is selected
  by default. **Build** is the default format on Windows. Linux and macOS targets still
  produce **Source** only.
- An **Update** row shows which game update the export will use, and a "From:" line
  shows where it comes from.
- **Install Update File…** installs a game update (.nsp) after checking that it belongs
  to the selected game. If no update is installed, exporting asks whether to install
  one or export without it.
- A game file with a bundled update, while updates are turned off for that game, is
  stopped before the export starts instead of failing at the end.
- The default output folder is `exports` inside the source folder when suyu runs from
  a source checkout (Git ignores it). Otherwise it is your Downloads folder.
- The progress bar follows the real work. The status line shows, for example,
  "Compiling 312/940 files (main)" or "Copying game data: X of Y MB".
- Packages copy your suyu settings (graphics, CPU, audio, system, applets). Debug and
  unsafe settings, folder paths, input devices and personal data are left out. With
  **Include custom game configuration** ticked, the game's own settings are added on
  top.
- **Include transferable shader cache** now works. Before, the cache went to the wrong
  folder, and the JIT package had its disk cache turned off. On the JIT package this
  removed a 5-second freeze at race start.
- Packages report the update's real version. Older packages showed "Ver. 1.0.0";
  re-export them to fix it.
- An exported game's title bar shows FPS, frame time, "Building N shaders" and
  the CPU backend, so you can tell when a stutter is a shader being built.
- Exporting the same game again is reliable. Old generated code is reused only when
  the game code matches, leftover modules are removed, and an old version number no
  longer carries over.
- Mismatched game data (base game data paired with update code, and similar mixes)
  is refused up front instead of producing a broken build.
- A **Source** export on Windows is labelled as C source code, and a **Build** export
  only reports success when the launcher actually compiled.

### Keys and firmware in exported games
- Exports never contain keys or firmware. An exported game reads them from your
  installed suyu: `%APPDATA%\suyu\keys` and `%APPDATA%\suyu\nand` on Windows, or the
  `user\` folder of a portable suyu. A custom NAND folder set in suyu is honoured.
- If `prod.keys` is missing, the game shows a dialog with the exact folder and the
  buttons **Install keys in suyu** (when the suyu that made the export is found),
  **Open folder** and **Quit**. Copying `prod.keys` into that folder works just as well.
- If firmware is missing, the game warns and offers **Continue anyway**. Mii screens
  and some menus may fail without firmware.
- Exported games now read the installed firmware. This fixes an empty "Select a Mii"
  screen in Mario Kart 8 Deluxe.

### Controllers in exported games
- The first gamepad becomes Player 1. More pads become Players 2–8 in the order they
  connect, as Pro Controllers.
- Unplugging a pad disconnects that player. Plugging it back in returns it to the same
  slot (Players 2–8; an empty Player 1 goes to the next pad that connects).
- Player 1 is never left empty: if all pads leave, the keyboard goes back to Player 1.
- Devices that aren't gamepads are ignored. Left and right Joy-Con halves combine
  into one player automatically. The F12 controls panel has **Combine Joy-Cons into
  one player** and **Split Joy-Cons into two players** buttons.
- The Home button works on gamepads.
- Choosing **Use keyboard** or **Rebind** in the F12 controls panel turns automatic
  assignment off for that package.
- Tested live with two pads (PowerA and Xbox Series X) at 60 fps in the JIT export.

### Steam
- **Add to Steam library when the export finishes** adds a non-Steam shortcut that
  runs the export's own program. It is named after the game and backend, for example
  "Mario Kart 8 Deluxe (suyu Dynarmic JIT)", "(suyu Hybrid JIT + AOT)" or
  "(suyu static AOT)".
- **…and replace an existing shortcut** removes only suyu's own shortcut for that game.
- Steam artwork (cover, banner, hero, logo, icon) is made from the game's icon. The
  optional **…and fetch cover art from Wikipedia** uses Wikipedia cover art instead;
  it sends the game's title to Wikipedia.
- Your other Steam shortcuts are kept byte for byte. If suyu can't fully read Steam's
  shortcut file, it leaves the file untouched.
- Restart Steam to see changes. Steam shows no description for non-Steam games; that
  is a Steam limitation.

### macOS (Apple Silicon)
- Apple Silicon Macs work again (community PR #1 by @mmkzer0, thank you). Rendering
  goes through MoltenVK and Metal.
- Fixed long stalls (0 fps for 10–40 seconds). The Mac JIT went from a 1.2 fps average
  to 56.6 fps, and RetroArch on Mac now reaches the race at about 59 fps.
- Fixed a crash when the game ends (0 crashes in 9 runs, against 1 in 3 before).
- Fixed a crash at renderer startup, a Metal window-surface lookup failure, and GPU
  cleanup after an error.
- Fixed several MoltenVK visual problems: copies between images with mismatched
  block formats, and output fixups that touched unbound attachments.
- Emulator threads use macOS priority classes (QoS), and the game window comes to the
  front when a game starts.

### RetroArch / libretro core (new)
- A Vulkan libretro core for Windows, Linux and macOS. It supports base game plus
  update loading with identity checks, TAS playback and core options.
- A "Game X.X FPS · N ms" readout is on by default (core option **Show Game
  Performance**). Trust it over RetroArch's own counter, which also counts repeated
  frames.
- Starting from a fresh RetroArch profile works: keys are picked up before boot, and
  bad or incomplete game files are rejected with a clear error instead of crashing.

### Android
- The Android app (APK) and an **ARM64 libretro core** build, with the stall fix
  above compiled in. The libretro core is an opt-in development build, separate from
  the app.
- It has only been run in the Android emulator, which has no GPU and shows about
  4–8 game fps. That is not a real-device result.

### Everyday usability
- **View → Resolution Scale** changes the internal resolution without opening
  Settings. A game's own resolution setting still wins, and the app tells you when
  that happens.
- The status bar shows which CPU backend is actually running and counts JIT fallbacks,
  or shows "NO JIT".
- The branch name no longer appears in the window title.

### Graphics fixes (all platforms)
- A shader pipeline that fails to build now skips that one draw instead of freezing
  the game.
- Shader resources are declared the way stricter drivers expect, which fixes shader
  validation failures.
- Texture storage support is checked against the format actually chosen. An empty
  texture slot is treated as "nothing bound" instead of causing a format error.

### Other fixes
- Shutdown: the GPU thread now finishes and stops before GPU services close. This
  fixed the Mac crash above.
- Windows: fixed memory corruption when a game closes. The renderer was destroyed after
  the GPU channels it still pointed at, and its last flush wrote into freed memory; it
  surfaced as an intermittent crash on exit. Caught with page heap at the exact write,
  then verified: 0 corruptions in 7 runs with the fix, while the old build still stops.
- Fixed a rare crash when a game thread ends, mostly seen while closing a game: the
  emulated kernel released a finished thread while holding the scheduler lock, so a
  lock it then needed could be "taken" without being owned. The thread is now released
  after that lock is dropped. 0 crashes in 8 debug-heap runs, against about 2 in 11.
- Adding, repairing and removing Steam shortcuts uses safe all-or-nothing writes.

## Performance

Mario Kart 8 Deluxe v4.0.0, game fps during a race (the game runs at up to 60).
Measured 2026-09-22.

| | Dynarmic JIT | Hybrid | Strict static |
|---|---|---|---|
| Windows x64 (RTX 3090) | 60 | 31–35 ¹ | **~25** (22 before this release's compiler change) |
| macOS Apple Silicon | 59–60 | not measured | **~58** (52–53 before) |
| Linux x64 (GPU shared with another job) | ~58 | not measured | did not reach the race (slow startup under investigation) |

¹ Measured before the compiler change below; it should improve too.

**Compiler change:** exported games now compile their generated code with full
optimisation (`/O2` on Windows, `-O2` on macOS and Linux) instead of `/O1`/`-O1`. Measured
in a race: Windows static +12.7% fps and 12.7% less CPU (3 runs each, every `/O2` run
faster than every `/O1` run); macOS static +11%. Exports take about 25% longer to build.
Re-export to get it.

For this game today, the **Dynarmic JIT export is the fastest**. Hybrid and static are
experimental. Speeding up pre-compiled code on x86 is the next focus.

Shader cache on the Windows JIT package: 55.7 → 58.8 average fps, the 5-second freeze
at race start removed, and the worst frames down from 66 ms to 26 ms.

## Known limitations

- Portable settings, the keys/firmware startup check and automatic controller
  assignment apply to **Windows** packages. Linux and macOS exports are Source only and
  have no bundled runtime.
- Steam shortcuts go to the first Steam account found on the computer.
- Re-exporting renames an existing Steam shortcut in place (for example to the new
  "(suyu Dynarmic JIT)" style names). Steam keys artwork and play time by a shortcut's
  name, so those start fresh for the renamed entry.
- A game that isn't in your suyu library is named in Steam after its file name.
- Joy-Con auto-assign and Combine/Split are covered by automated tests but haven't been
  tried with real Joy-Cons yet.
- Linux static exports start slowly and did not reach the race in testing.
- Android has not been tested on a real device, so its real performance is unknown.
- In the Android emulator, black margins around the picture come from the emulator's
  camera-cutout setting, not from suyu.
- On macOS RetroArch and Android, RetroArch's FPS counter reads higher than the game's
  real frame rate; use the core's own readout.
- Static mode is per-title. Smash Ultimate in strict-static mode still hits uncovered
  code.
- Downloads never include games, generated game code, keys, firmware or saves.
  Standard downloads include Dynarmic; only the separate `no-jit` builds leave it out.

## For developers

### Static recompiler: ABI 5
- **ABI 5** validates generated image revision, instruction coverage and memory guards
  more strictly. ABI 4 images are rejected at build time, by the CMake header check,
  and again at runtime, by `recomp_image_abi()`.
- **Correctness over speed:** ABI 5 deliberately reverts two experimental
  speed-ups from the iOS branch.
  - Per-entry code verification is restored. The shared generation-counter guard
    (check-once code guard) has been removed, and the `guard_generation` slot is kept
    for layout only. Hosts must set it to null.
  - The native AArch64 host-FP fast path is removed. It didn't raise guest FPSR
    flags, and its results depended on the ambient host FPCR.
  - FP conversions now use integer significands with exact FZ, rounding and sticky
    FPSR behaviour. Recovering that speed without losing correctness is future
    work.
- **Relocation policy `rtld-only`:** relocations are pre-applied to rtld only, which
  matches Dynarmic's behaviour. Fixes deferred `nn::ro` NRO imports never binding
  (0/909 fighter slots bound in Smash). The rejected alternatives remain available
  behind `SUYU_RECOMP_RELA_POLICY`.
- **Correctness fixes:**
  - Guarded guest reads are safe across page boundaries.
  - Page-crossing accesses no longer take the host-pointer fast path.
  - The exclusive reservation is cleared when a core switches guest threads.
  - Undefined weak symbols resolve to zero.
  - Exclusive state is cleared per thread.
  - Shifted-register encodings that are undefined for `sf==0 && imm6>=32` are
    refused and counted as uncovered.
  - Word-level normalisation and sticky flag scans.
  - Fixed-point conversion and FPSR behaviour have synthetic regression coverage.
- **Stricter loading:** known base RomFS / updated ExeFS and standalone NCA code/data
  mismatches are rejected. Two non-base views from an installed update still need
  title-specific verification before a package can be called playable.
- Hybrid's frequent JIT fallbacks for one vector instruction are deliberate and help
  its performance.
- Generated C no longer inherits the host's `-Werror`.
- Keys and window naming for static exports now work on non-Windows hosts.
- **Env-gated diagnostics** (inert unless set): targeted PC sampling, handover
  cutoffs, a guest-thread dump with arbiter keys, and a kernel lock trace.

### Core
- **arm64 exclusive monitor:** guest spin loops could saturate Dynarmic's global
  exclusive-monitor lock and starve other cores (0 fps for 10–40 s). The fix is
  enabled for arm64 GCC/Clang builds only (macOS, Linux arm64, Android); x64 is
  unchanged.
- **Shutdown order:** the GPU thread is drained and joined before GPU services close.
  macOS: 0/9 exit crashes, against 1/3 before.
- **Renderer destruction order:** `GPU::Impl::~Impl` now destroys the renderer before
  `channels`/`scheduler`. Otherwise `~RasterizerVulkan` → `Scheduler::Finish` →
  `InvalidateState` ORs into a freed channel's Maxwell3D dirty flags (Windows 0xC0000374
  at a later free). Found with per-process full page heap.
- **Kernel thread release:** `KThread::FinishTermination` now calls `Close()` after its
  `KScopedSchedulerLock` scope. A `KLightLock` wait nested inside the scheduler lock never
  blocks for host threads, so `Finalize()` (TLS unmap under the page-table lock,
  `UnregisterThread` under `m_list_lock`) could "acquire" a contended lock without owning
  it, corrupting the lock tag and ending in `KThread::EndWait` on a stale wait queue.
- Exported games read the installed firmware. Without it, the MK8D Mii thread was
  killed in strict static mode.
- The application process is released before the kernel is torn down, which fixes
  a shutdown-ordering crash.
- The fastmem arena is placed elsewhere when the low address window can't hold it.
  This is needed on 16 KiB-page hosts such as Apple Silicon.
- The frontend can override the reported application version, and the override is
  saved in settings.
- Explicit base/update content selection goes through a read-only provider and
  rejects a second, unrelated launch path.
- Logging is rate-bounded per call site, so one repeating message can't flood the
  log.

### Frontend and packages
- `suyu -install-keys` and `suyu -install-firmware` open **Tools → Install Decryption
  Keys** / **Install Firmware** once the window is up. An exported game that is missing
  either starts suyu this way.
- Exported packages look for `prod.keys` or `prod.keys_autogenerated` in the installed
  suyu's `keys` folder, and for firmware in the package's own NAND first, then the
  installed one (including a custom `nand_directory`).
- Controller auto-assignment is stored per package under `[Controls]` as
  `auto_assign_controllers` and `auto_assigned_pads`.
- Steam shortcut edits preserve other entries byte for byte and leave
  `shortcuts.vdf` untouched when it can't be fully read.

### libretro
- Repeated frames are marked as repeats.
- The **Show Game Performance** core option (on by default) applies immediately.
- The black margins seen in the Android emulator came from an emulator camera-cutout
  setting, not the core.

### Tooling and measurement
- `suyu-cmd -t` / `--tas` replays a TAS script headlessly.
- `SUYU_CMD_PERF_SAMPLE=1` logs `game_fps`, `system_fps`, `frametime_ms` and `speed`
  once per second, as a series. Stalls show up as gaps instead of disappearing into
  an average.
- `SUYU_CMD_CAPTURE_DIR`, `..._FIRST_SEC` and `..._INTERVAL_SEC` take periodic
  screenshots. Bounded capture runs stay off the active desktop.
- The video core attributes frame stalls to where the wall-clock time actually goes.
- `scripts/mk8d-tas/` adds a source-only 6,001-frame TAS for MK8D v4.0.0. It covers
  menus, then Mushroom Cup, then the opening of Mario Kart Stadium.
- iOS research: a separate static-AOT diagnostic host lives under `research/ios`.
  It ran signed no-JIT gameplay frames on an iPhone 16 Pro Max. It's research
  only and isn't a release target. The ~2× iPhone speed-ups tried there are not
  in ABI 5; see above.

### Build and release
- The build no longer requires the Qt Svg component. The macOS MoltenVK
  configuration is fixed.
- CoreTiming tests no longer depend on the order they run in.
- `suyu-v0.0.11-source.tar.gz` includes all 37 submodules. The source archives
  exclude opaque prebuilt binaries, developer caches and generated proof outputs.

### What was tested
- **Windows:** GUI, CLI and libretro builds. Export regression fixtures. Nine libretro
  lifecycle modes, plus TAS and core-options smoke tests. MK8D v4.0.0 JIT, Hybrid and
  static exports measured in a race (table above), and two-pad controller assignment
  in the JIT export.
- **Linux:** GUI, CLI and libretro builds. CTest 71/71, focused recompiler tests 24/24.
- **macOS ARM64:** GUI, CLI and libretro builds. CTest 55 passed, with 16 expected
  fastmem skips on 16 KiB pages. Focused tests 24/24. JIT, static and RetroArch reached
  the race.
- **Android:** the ARM64 debug APK built and its debug signature verified; release
  signing was not tested. The opt-in libretro core built and showed on-track movement
  in a software emulator (low fps, not a real-device benchmark).
- **Strict-static MK8D v4.0.0:** the TAS replay reached a rendered, controllable race
  segment with zero JIT fallbacks and zero critical errors. This is a per-title test,
  not a compatibility guarantee.
- Not established: firmware applet CPU-backend attribution.
